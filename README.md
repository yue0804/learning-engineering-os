# learning-engineering-os

私有学习仓库。承接 Learning & Engineering OS 10.0 的学习与工程证据。

## 为什么需要这个仓库

上游课程只提供材料，不提供「我做过」的证据。本仓库只做四件事：

1. 让**上游引用**与**自己的产出**永远可区分；
2. 让**文件已生成**与**本人已掌握**永远分开登记；
3. 保留可复核的**真实运行结果**，而不是描述性结论；
4. 为每一段学习保留**准确断点**，中断后能原地续上。

## 仓库不替代什么

- 不替代 V10.0 总纲、协议与人物模型；三份文档仍是路线与判断的权威来源，本仓库只是执行层证据。
- 不替代课程本身。仓库里出现某个文件，不代表该内容学过。

## 三条口径（判断任何记录是否有效）

| 口径 | 含义 | 违规示例 |
|---|---|---|
| 引用 ≠ 掌握 | 收藏、克隆、抄写上游材料，均不计入学习完成 | 把 hello-algo 的示例代码拷进 work/ 就记为已掌握 |
| 示例 ≠ 练习 | 上游仓库已有实现，不等于自己写出过 | 未独立实现即引用上游答案 |
| 生成 ≠ 完成 | 文件由助手生成，只说明文件存在 | 在 PROGRESS.md 由助手代填已完成 |

## 目录

| 目录 | 放什么 | 谁写入 |
|---|---|---|
| docs/ | 体系文档索引、版本登记、许可与引用记录 | 阿序为主 |
| resources/ | 上游资源的链接、版本、所用章节（不落全文） | 阿序为主 |
| plan/ | 每日任务与准确断点 | 阿序起草，玥确认 |
| work/ | 原创练习与项目代码 | 玥本人 |
| records/ | 真实运行结果与输出 | 玥本人 |
| corrections/ | 错因订正与复测记录 | 玥本人 |
| STATUS.md | 文件生成状态 | 阿序 |
| PROGRESS.md | 本人学习完成状态 | 仅玥本人 |

## 状态为什么分成两份

STATUS.md 回答「这个文件是谁生成的、依据是什么」，它可以自动更新。
PROGRESS.md 回答「玥本人是否已经掌握」，它只能由本人确认。

两者混写，就会出现「仓库看起来很完整、实际没有学过」的假象。这是本仓库首要防止的错误。

## 不得进入本仓库的内容

- BusTub 等课程的解答（官方要求课程学生与课外学习者均不公开）；
- 第三方课程材料全文、大体积压缩包与数据集（只登记链接、版本、章节）；
- 个人信息、账号令牌、API Key；
- 未经复核的完成结论。
